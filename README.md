## 它解决什么问题

- **一份简历投十个岗位，每个岗位都要手工改一遍。** 系统解析 JD，自动判断每段经历该**突出、保留、弱化还是排除**，生成岗位定向版本。
- **通用 AI 改写不针对岗位，还容易编造。** 所有生成内容都受**事实门禁**约束：只能引用已确认的简历事实，模型不可用时降级为本地规则并在界面上标出来源。
- **面试准备和真实经历脱节。** 模拟面试只针对「这个岗位 + 这份简历」提问，逐题评分并给出待改进点，复盘后再评估。

系统面向 **AI 产品、技术产品、智能硬件** 等方向，也可用于校园招聘与实习申请。

## 核心能力

| 模块 | 能力 |
|---|---|
| **岗位理解** | JD 结构化解析，提炼 2~3 个岗位关键词与关注点；识别公司、岗位、地点、核心要求 |
| **匹配度分析** | 简历 × 岗位匹配度评分（0~100 圆环）+ **为什么匹配 / 哪里不匹配 / 是否值得投递** |
| **简历优化** | 经历四分类（突出 / 保留 / 弱化 / 排除），原文对照 + 人工事实确认 + 最终版本审批 |
| **简历工作台** | 直接编辑简历**原始文字**；支持拖拽 PDF 上传；Typst 模板生成 PDF |
| **模拟面试** | 问题预览 → 逐题作答 → 评分/优点/待改进 → 追问 |
| **面试记录库** | 按「公司 + 第几次面试」归档真实题目、回答与复盘，沉淀为可复用资产 |
| **复盘与补强** | 面试复盘、补强建议、再评估，形成「面完还能变强」的循环 |
| **证据库** | 8 步事实流转：录入证据 → 建立主张 → 解析岗位 → 匹配差距 → 定位成稿 → 主张审计 → 确认定稿 → 渲染评估 |
| **网申资料** | 集中管理身份证、家庭情况等敏感字段；**不写入简历**，助手也读不到 |
| **AI 求职助手「顺顺」** | 流式问答、多会话历史保留、可联网搜索、可读岗位上下文 |
| **投递看板** | 状态机管理（待投递 → 已投递 → 笔试 → 面试 → Offer），**可逐级推进，也可退回上一阶段** |

### 一、求职主线

#### 1. 总览 —— 一条清晰的求职路径

四步路径（找岗位 / 写简历 / 投递跟进 / 面试题库）+ 跨档案汇总统计 + 最近岗位。

![总览](docs/screenshots/01-home.png)

#### 2. 岗位 —— 关键词、匹配度圆环、投递状态一表看清

表格里每个岗位都带 **2~3 个岗位关键词**、**简历匹配度圆环**（附「值得投递 / 先补齐再投 / 暂不建议投递」结论）与投递状态，行内可直接**推进 / 退回**。

![岗位](docs/screenshots/02-missions.png)

#### 3. 点岗位名 —— 右侧滑出「岗位匹配分析」

**点一下岗位名**，右侧滑出侧栏：匹配度圆环 + **为什么匹配 / 哪里不匹配 / 是否值得投递**，逐条对应简历证据；**再点一下同一岗位名**即进入完整岗位页面（侧栏底部也有入口）。

![岗位匹配侧栏](docs/screenshots/22-job-match-drawer.png)

#### 4. 简历中心 —— 上传、改原文、管理版本，一处完成

合并了原「工具栏 → 上传简历」入口：**拖拽 PDF 直接建档案**、按档案 ID 恢复、删除档案；**简历工作台**里直接编辑简历原始文字（保存原文 / 保存并重新提取事实）；下方是各岗位生成的**定向版本表格**。

![简历中心](docs/screenshots/03-resumes.png)

#### 5. 投递 —— 记录每一步，可进可退

每条投递记录都能**推进**到下一阶段，也能**退回**上一阶段，并可「记面试问答」沉淀题目与回答。

![投递](docs/screenshots/04-tracker.png)

#### 6. 面试题库 —— 题目准备与面试记录合二为一

按「公司 + 第几次面试」选择场次，同一页里准备题目、记录真实被问到的问题。每道题都能看到「用哪段经历回答」与「可以说的事实」，参考答案由模型基于简历生成。

![面试题库](docs/screenshots/05-question-bank.png)

#### 7. 顺顺 —— AI 求职助手

流式回答、**多会话历史保留**（关掉再进不丢）、可读当前岗位上下文、可选联网搜索与写入权限。

![顺顺 AI 助手](docs/screenshots/06-assistant.png)

### 二、岗位准备工作流

一个岗位从录入到复盘，顺着顶部流程条逐步推进：**01 岗位 → 02 简历 → 03 模拟面试 → 04 面试记录**。

#### 1. 新建岗位 —— 粘贴 JD 即可

粘贴完整 JD（可选填来源链接），一键识别岗位信息。

![新建岗位](docs/screenshots/09-mission-new.png)

#### 2. 岗位确认 —— 核对识别结果，选择简历来源

查看识别出的公司、岗位与关注点，同时保留原始 JD 原文以便核对。

![岗位确认](docs/screenshots/10-mission-role.png)

#### 3. 简历匹配度 —— 评分 + 为什么匹配 / 哪里不匹配

岗位页面同样带**匹配度圆环**与逐条依据：为什么匹配（引用简历事实）、哪里不匹配（对照岗位要求），并给出「是否值得投递」的建议。

![岗位页匹配卡](docs/screenshots/23-mission-match-card.png)

#### 4. 证据补强 —— 把最容易被追问的部分补成真实证据

系统找出证据偏弱的经历，先用你已经做过的事实补齐，确实没有再补完整项目。

![证据补强](docs/screenshots/12-mission-proof.png)

#### 5. 岗位定向简历 —— 一岗一版

基于同一份原始简历，按岗位要求重新组织经历与措辞，生成该岗位专属版本。

![定向简历](docs/screenshots/13-mission-resume.png)

#### 6. 模拟面试 —— 问题预览 + 逐题评分

先看问题预览与考察点，再逐题作答；每题完成后给出评分、优点与待改进点。

![模拟面试](docs/screenshots/14-mission-interview.png)

#### 7. 面试记录 —— 把真实面试沉淀下来

记录面试结果、轮次、被问到的问题、需要加强的地方与复盘。

![面试记录](docs/screenshots/15-mission-outcome.png)

#### 8. 面试复盘 —— 本次表现、做得好与需加强

汇总所有问题与回答，并给出项目补齐方向；「本次表现」给出可执行的下一步。

![面试复盘](docs/screenshots/19-proof-debrief.png)

## 快速开始

### 方式一：一键启动（Windows）

```bat
start-demo.cmd
```

脚本会同时拉起 API（`127.0.0.1:8000`）与前端（`127.0.0.1:3000`），并使用 `.runtime/demo-career.db` 作为演示数据库。

### 方式二：手动启动

**1. 启动后端 API**

```bash
cd apps/api
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt

# 配置模型（见下方「模型配置」）
set DATABASE_URL=sqlite:///G:/myself/ai-career/.runtime/demo-career.db
set PYTHONPATH=.
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

**2. 启动前端**

```bash
cd apps/web
npm install
set NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000
npm run dev -- -H 127.0.0.1 -p 3000
```

打开 **http://127.0.0.1:3000** 即可。

### 模型配置

在**项目根目录**创建 `.env`（已被 `.gitignore` 忽略，不会进入版本库）：

```env
OPENAI_API_KEY=你的密钥
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
```

- 支持任意 **OpenAI 兼容**端点，例如 DeepSeek（会自动关闭 thinking 模式）。
- 岗位关键词、匹配度分析、参考答案等均由该模型生成；**模型不可用时会降级为本地规则**，并在界面上标注来源，不会让页面白屏。
- 简历预览 / PDF 导出依赖 [Typst](https://typst.app/)：下载 `typst-x86_64-pc-windows-msvc.zip` 解压到 `.runtime/typst-0.15.1/` 即可（缺失时仅影响预览与 PDF）。

## 技术架构

| 层 | 技术 |
|---|---|
| **前端** | Next.js 15（App Router）· React 18 · TypeScript · Tailwind CSS |
| **后端** | FastAPI · SQLAlchemy 2.0 · Alembic（25 个迁移）· Pydantic 2 |
| **数据库** | SQLite（演示）/ PostgreSQL（生产） |
| **文档解析** | PyMuPDF（PDF 文本提取） |
| **模型** | OpenAI SDK，兼容任意 OpenAI 式端点 |
| **知识库** | `knowledge/interview_skills/`（企业面经）· `knowledge/resume_skills/`（简历写作规范） |

**事实门禁**：所有对外输出的内容（匹配理由、参考答案、简历改写）只能引用已确认的事实（`READY / CONFIRMED / SUPPORTED` 的主张与已确认版本的简历要点），系统不编造经历与数字。

## 设计原则

1. **原始简历是唯一事实来源。** 改写只改变措辞与取舍，不新增未经确认的事实。
2. **生成与确认分离。** AI 负责建议，人负责确认；每条进入简历的内容都可回溯到原文。
3. **降级可见。** 模型不可用时走本地规则，并在界面标注来源，绝不静默失败。
4. **一岗一版。** 每段经历针对岗位做突出 / 保留 / 弱化 / 排除，而不是套用一个通用模板。
5. **闭环。** 面试的结果回流到证据与简历，让每一次面试都变成下一次的弹药。
