## 扩展 v1.3.0：找到「读取恒失败」的真正根因（本轮，重要）

- 报错 `[{"documentId":...,"frameId":0,"result":null}]` 的真正原因**不是 BOSS DOM**，
  是我方代码缺陷：`chrome.scripting.executeScript({ files: [...] })` 在 MV3 下
  **不返回脚本的最后一个表达式**，results[0].result 恒为 null。
  → extract.js 一直跑成功并抽到了内容，只是结果从来没传回后台；所以让用户「F5 刷新」永远无效。
- 修法（通用套路，以后写 MV3 扩展都照这个来）：files 注入 + 结果写 DOM 属性/全局/
  chrome.storage，再用 `func: () => ...` 主动回读；用 func 才能拿到返回值。
- three-channel 回读：documentElement[data-ai-career-capture] → window.__AI_CAREER_CAPTURE__
  → chrome.storage.local.aiCareerCapture；注入前先 clearCapture 防旧值。
- 弹窗顶部加「扩展版本 vX.Y.Z」，让用户能确认是否真的重载到新版本（此前多轮
  无法区分是「用户没重载」还是「代码没修好」）。

## 扩展 v1.3.1：第二个根因（重复注入的顶层 const SyntaxError）

- v1.3.0 用户确认已加载，仍报「注入成功但页面没写回结果」，三条回读通道全空。
- 复现实验（Playwright 同一文档 addScriptTag 两次）拿到铁证：
  第 2 次 → `SyntaxError: Identifier 'CAPTURE_ATTR' has already been declared`，
  注入 API 却仍返回 OK、result=null → 脚本一行都不执行。
  同一个隔离世界的顶层 const/let 进共享全局词法环境，重复注入必炸。
- 修法（MV3 内容脚本通用铁律）：
  1. 被 `executeScript({files})` 注入的脚本**一律 IIFE 包裹**，禁止顶层 const/let；
  2. 要拿结果必须用 `func` 注入——`files` 注入 result 恒为 null；
     做法是把函数挂到 `window.__aiCareerExtract`，background 用 func 调用取 JSON。
- E2E 4c 改成「连注入两次 + 断言 pageerror 为空」的回归，11/11 通过。提交 429b46d。
