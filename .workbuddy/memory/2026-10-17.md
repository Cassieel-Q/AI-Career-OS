### 修掉的 5 个真实缺陷（都在 job_ingest_service / job_ingest_routes）

1. **Greenhouse 去重完全失效**：适配器在 `normalize_job` **之后**才把 company 从空改成
   board token，但没重算 `dedupe_key` → 库里存的 key 是用空公司名算的，
   下次 `find_duplicates` 按真实公司名现算永远匹配不上，同一批岗位每次都被当「新增」。
   → 新增 `retag_company()`，改写公司名后必须重算 key。
2. **保存时启发式解析覆盖来源字段**：`save_collected` 只在启发式结果为空时才补来源字段，
   RemoteOK 岗位被切成「Remote / Independent Contractor」（取自 JD 首行），
   岗位库里显示的公司名和岗位名是错的 → 改为来源字段优先。
3. **抓取无体积上限**：`fetch_url_text` 整体读入响应体 → 流式读取 + 5 MiB 上限。
4. **招聘板标识未过白名单**：`../..` 路径穿越、`?` 截断 query → `validate_board_token()`。
5. **去重指纹漂移**：随机 token 剥离后残留 `(# )` 空括号 → `_EMPTY_BRACKET_RE` 一并清掉。

### 两个重要教训

- **本机 `HTTP_PROXY` 会让 httpx 误报 404**：环境里设了代理时 httpx 默认 `trust_env=True`
  会把 127.0.0.1 的请求也发给代理，代理转发后路径写成绝对形式 → 后端 404。
  采集脚本必须用 `httpx.Client(trust_env=False)`。排查花了不少时间。
- **改 `httpx.Client.get` → `client.stream` 会让 mock `get` 的测试失效**（不是缺陷，
  是测试与实现耦合）。改实现后记得同步更新 mock 目标。
