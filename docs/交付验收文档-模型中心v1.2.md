## 1. 本轮范围

「AI 模型中心」：普通用户在 **设置 → AI 模型** 页面即可完成模型配置（无需编辑 `.env`），并统一驱动所有 AI 模块（顺顺、JD 解析、岗位匹配、简历定向改写、模拟面试等 10 个模块）。

不包含：新增 Agent 能力、Resume Studio / 18 套模板 / BOSS 导入 / 求职管理的功能变更（只做回归保护）。

核心交付物：

| 组件 | 文件 | 说明 |
| --- | --- | --- |
| 统一网关 | `apps/api/app/model_config_service.py` | 配置 CRUD、优先级链、连接测试、SSRF 校验、能力探测 |
| 密钥存储 | `apps/api/app/secret_store.py` | Windows DPAPI 用户级加密；失败不静默降级明文 |
| 访问控制 | `apps/api/app/local_access.py` | Origin 白名单（回环任意端口）+ 自定义头 + Sec-Fetch-Site |
| API 路由 | `apps/api/app/model_config_routes.py` | `/api/v1/model-configs*` |
| 前端 | `apps/web/app/model-center.tsx`、`model-onboarding.tsx`、`settings/page.tsx`、`model-config.ts` | 设置页「AI 模型」标签 + 首页首用引导 |
| 测试 | `apps/api/tests/test_model_config.py`（53 项）、`tests/conftest.py`（隔离 fixture） | Mock Provider，不发外部请求 |
| 报告 | `docs/模型中心测试与安全报告.md` | 上一轮的详细测试与安全结论 |

配置优先级：**用户在页面保存并启用的配置 → `.env` 旧环境变量回退 → 未配置（本地功能照常）**。
用户配置损坏（无密钥/换地址未重填密钥）时自动回退 `.env`，并在设置页标注「已回退」及原因。

## 4. 功能验收清单（人工/E2E）

打开 `http://127.0.0.1:<前端端口>/settings`，切到「AI 模型」标签。

### 4.1 新增配置（DeepSeek 示例）
1. 提供商选 `DeepSeek` → 页面自动填 `https://api.deepseek.com` 与常见模型。
2. 名称随意；API Key 填服务商密钥；模型 ID 可下拉可手改。
3. 点「保存并新增」。
4. **预期**：列表出现该配置，`key_masked` 只显示尾 4 位（如 `***7890`），无任何明文；它成为默认配置。

### 4.2 生效验证
保存并设为默认后：
- 设置页「AI 模型状态」表格里 10 个模块的「生效来源」从 `.env 环境变量` 变为「我的配置」；
- 顺顺发一条消息，能正常流式回复（说明网关已路由到新模型）；
- 简历定向改写、JD 解析、模拟面试同样可用（不需要重启后端，新会话即生效）。

### 4.3 编辑但未改密钥
编辑配置改模型 ID → 保存。**预期**：不要求重填密钥，`key_present` 仍为 true。

### 4.4 更换提供商/Base URL 但不重填密钥
把 base_url 换成另一个服务商地址 → 保存。**预期**：配置被标记「换地址后密钥未验证」，不再被网关使用（避免把 A 家密钥发给 B 家）；AI 自动回退 `.env` 并在页面提示。重填新密钥后恢复。

### 4.5 删除配置
删除默认配置。**预期**：立即失效，AI 回退 `.env`；后端不能再用该密钥（密文随之删除）。

### 4.6 连接测试
1. 不勾选「我了解测试可能产生少量费用」→ 点「测试连接」。**预期**：前端直接拒绝，不发请求。
2. 勾选后再测。**预期**：逐步返回 地址 → 密钥 → 模型 → 对话 → JSON → 工具调用 → 流式 的分项结果；失败给出人话原因（如「密钥被拒绝」「无法连接该地址」）。
3. 测试失败**不得**影响已保存配置的可用性。

### 4.7 Ollama 预设
提供商选 `Ollama`，`base_url=http://127.0.0.1:11434`，不需要密钥。若本机没跑 Ollama，测试连接应报「无法连接该地址」，页面其余功能不受影响（已有实机截图 `docs/screenshots/v1.2/03-test-fail-ollama.png`）。

### 4.8 首用引导
清空配置后打开首页。**预期**：出现四步引导（导入简历 → 配置模型可跳过 → 导入岗位 → 第一份岗位版简历）；跳过配置时明确提示「未配置 AI 模型，你仍可以管理岗位、编辑简历和导出 PDF」（截图 `05-onboarding.png`）。

## 6. 已知问题与设计取舍

1. **真实提供商测试 `NOT_RUN`**：本轮未消耗任何真实 API 费用。DeepSeek 连通性由 `.env` 回退链路间接验证（顺顺流式实测正常）。复测时可自行在设置页点「测试连接」。
2. **端口漂移**：3000/3001 被本机其他项目长期占用，前端当前落 **3002**。启动器会自动处理并打印实际端口；2026-10-18 已修复漂移端口的 CORS（此前会把整页打成 `Failed to fetch`）。
3. **本机模型端口范围**：回环地址任意端口可用（Ollama 11434、LM Studio 1234、自建网关等），但 AI Career OS 自身端口 8100/8770 与常见敏感服务端口被拒绝（见 §7 F2）。
3. **`.env` 兼容**：旧环境变量继续生效并明确标注来源；未经用户在页面操作不会覆盖。
4. **多会话**：模型切换后，顺顺**新会话**用新配置，**旧会话历史保留**（消息记录不迁移模型）。
5. **能力差异**：不支持工具调用的模型被选为顺顺模型时，会如实提示能力不足，不伪装工具调用成功。

## 7. 首轮复测发现的问题与修复（2026-10-18 复测报告）

依据：`docs/qa/model-center-v1.2-2026-10-18/复测报告.md`。复测结论为「暂缓无条件验收」，指出 1 个 P1 功能缺陷、1 个 P2 边界不一致。**两项均已修复并补齐回归。**

### F1（P1，已修复）：Ollama 等无密钥本机模型保存后无法使用

现象：Ollama 预设 `requires_key=false`，创建时能保存，但网关读取与「测试连接」无条件要求密钥 → 10 个模块全部 `user-broken`，测试返回 `key_required`（还没连服务就失败）。

修复（`apps/api/app/model_config_service.py`）：

- 新增 `config_requires_key(item)`：以配置里固化的 `requires_key` 为准，缺省回落到提供商预设；
- 创建/更新时把 `requires_key` 写进配置（换提供商时按新预设重算），用户在自定义网关下也可显式声明不需要密钥（`ConfigIn.requires_key`）；
- `_settings_from_config`（网关读取）与 `test_connection`（已保存配置路径）都遵守同一判断；无密钥时直接发起连接，本机服务未运行返回 `unreachable`；
- 不需要密钥的服务仍可携带**可选密钥**（自建网关带鉴权的场景）；
- 列表/状态接口新增 `requires_key` 字段，前端对 Ollama 显示「本机模型不需要密钥，可留空」。

新增回归（三条路径统一矩阵，防止规则再次漂移）：

```
test_keyless_local_config_is_usable_by_gateway          # 网关调用路径
test_keyless_local_config_test_connection_reaches_out   # 已保存配置测试路径
test_keyless_local_draft_test_connection                # 草稿测试路径
test_keyless_local_config_can_carry_optional_key
test_cloud_provider_without_key_still_rejected          # 云模型仍必须有密钥
```

实测：创建无密钥 Ollama 后，10 个模块由 `user-broken/false` 变为 `user/true`；测试连接返回 `unreachable`（不再 `key_required`）。

### F2（P2，已修复）：本机模型端口的产品边界统一

现象：后端实际放行回环任意端口（黑名单制），页面却写「只允许本机 Ollama 11434」，说明与实现不符。

**确定的产品边界**：本机回环（`127.0.0.1` / `localhost` / `::1`）**任意端口可用**（Ollama 11434、LM Studio 1234、vLLM/自建网关各异）；仍拒绝：局域网与其它机器地址、公网非 HTTPS、敏感服务端口（22/3306/3389/5432…）、特权端口（<1024 且非 11434）、**AI Career OS 自身端口（8100 后端 / 8770 浏览器桥，防自指）**。

已同步：后端 `_SELF_LOCAL_PORTS` 与 `validate_endpoint`、提供商预设 hint、`model-center.tsx` 页面说明，并新增测试锁定：

```
test_local_endpoint_ports_allow_ollama_and_alternatives   # 11434/1234/18123/8000 允许
test_local_endpoint_ports_reject_self_and_sensitive_ports # 8100/8770/3306/3389/5432/80 拒绝
test_lan_and_remote_hosts_still_rejected                  # 192.168.x / 10.x 等依旧拒绝
```
