## 四、具体问题清单（按优先级）

### P0 — 必须先修

1. **经历筛选：不相关经历该砍却被高亮**  
   - 现象：校园书店收银、外卖、咖啡师等金标 OMIT，模型常给 KEEP_AND_HIGHLIGHT。  
   - 例：syn-match-001/002 收银经历。  
   - 影响：投递版简历被灌水，重点项目被挤占。

2. **经历筛选：关键相关经历被误砍（critical omit）**  
   - 现象：金标应 KEEP_AND_HIGHLIGHT 的创作/A-B 测试等经历被标 OMIT（至少 2 次）。  
   - 影响：岗位最相关证据丢失。

3. **学历字段抽取失败**  
   - 现象：JD 写「本科」等，education 准确率仅 0.125。  
   - 影响：岗位门槛展示/后续门控不可信。

4. **面试准备包泄漏 demo / CURATED 文案**  
   - 现象：5 个包里 2 个仍检出 demo；页面可能出现「…（CURATED，非合成演示）」当要点。  
   - 根因（已审计）：mission_provider 引用键只认旧字段、未接 interview_pack_intel 五处接线。  
   - 对应验收项：RISK-ACC-003。

5. **参考回答 / 改写可能编造简历里没有的事实**  
   - 历史 QA：把「分析 50 篇内容」说成「访谈 50 位创作者」。  
   - 本轮人工分未打（UNRATED），风险仍开放。  
   - 对应：RISK-ACC-001。

### P1 — 尽快修

6. **Studio 投递预览 vs 档案源「缺联系方式」假阳性**  
   - Studio 已有联系方式时，档案检查仍可能报缺。  
   - 对应：RISK-ACC-002；浏览器深比因未绑简历本轮 NOT_RUN。

7. **经历 decision 与中文 why 文案可能矛盾**  
   - OMIT 却写「建议保留」。对齐函数有单测，端到端仍要盯。  
   - 对应：RISK-ACC-004。

8. **JD 解析调用链不唯一 + 身份修改传播**  
   - MissionProvider.parse_jd vs jd_analysis_provider 需钉死；改公司/职级后筛选/改写是否用新身份。  
   - 对应：RISK-ACC-005（identity PATCH API 本轮 PASS）。

9. **必备要求（must_have）对齐弱**  
   - 软召回 0.25，后续筛选/面试题依据会偏。

### P2 / 工程

10. 模拟面试英文 422、英文题面等历史 E2E 问题：本轮 /missions 主路径未完整复测到交卷。  
11. 评估器曾用期望值冒充实际结果假通过——**已修**（缺实际 → NOT_RUN）。  
12. 集成未上 GitHub，外部分享/朋友网页测需另部署。

## 六、建议下一轮修法（给各车道）

1. 简历优化：经历四分类校准（OMIT 负例 + critical 高亮正例），压掉「全高亮」。  
2. JD 分析：学历与 must_have 抽取回归（中文学历词表）。  
3. 面试包说明：把 interview_pack_intel 五处接进 mission_provider，清 demo 泄漏。  
4. 投递导出 + PDF：统一 Studio 为投递 SoT，消假「缺联系方式」。  
5. 面试参考回答：加事实门控（只能用已确认 bullet）。
