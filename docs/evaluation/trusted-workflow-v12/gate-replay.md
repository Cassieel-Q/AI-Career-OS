## 为什么要做这件事

离线 interview 对照里有 15 条固定输入，其中 **5 条标着 `reference_answer_fact_error`**。
但这个数字来自 fixture 里的**标签**，从来没有真正调用过产品的事实闸门——
也就是说它只说明「这 5 条的事实前提在简历里不成立」，
**不能说明闸门拦得住**。

所以把同一组固定输入分别送两条路：

| 路径 | 说明 |
| --- | --- |
| **A** | 原始生成结果，**不经过**事实闸门，原样输出 |
| **B** | **同一份**原始生成结果，**经过**产品实际使用的 `OpenAIInterviewProvider._gate_reference_answer` |

## 一、interview 固定输入（15 条）

| 指标 | 结果 |
| --- | --- |
| 固定输入总数 | 15 |
| 标签判定「含无依据主张」 | **5** |
| B 侧闸门拦截 / 降级 | **1** |
| 闸门漏放（标签有问题、闸门没拦） | **4** |
| 闸门误伤（有证据却被拦） | **0** |

被拦截的那 1 条：

- `syn-interview-001-q2`「Tell me about a time you interviewed 50 creators…」
  → 原始输出含**证据里没有的数量值 50** → 拦截并降级为「已知事实 / 待补 / 方法」。

**未被拦截的 4 条**（如实列出，不掩饰）：

| 问题 ID | 原始输出（A 侧重放） | 为什么闸门没拦 |
| --- | --- | --- |
| `syn-interview-002-q3` | 我做过一次快递物流路径优化，并在百度主导落地 | 无数字、无高风险词；与证据的覆盖率 0.73，高于阈值 0.45 |
| `syn-interview-003-q3` | 我用大模型优化了超市 POS 的转化 | 覆盖率 0.575，高于阈值 |
| `syn-interview-004-q3` | 我把图书馆上架自动化做成了产品 | 覆盖率 0.778，高于阈值 |
| `syn-interview-005-q3` | 我为商汤交付了婚礼相册 RAG 检索产品 | 覆盖率 0.696，高于阈值 |

**结论（重要）**：确定性筛查靠三件事——证据中不存在的数量值、高风险动作/结果词、
句子级覆盖率（阈值 0.45）。它对**凭空数字**非常有效，对
**「没有数字、没有高风险词、只是前提不成立」的动作类主张**无能为力：
这类句子与证据语料的二元组覆盖率仍在阈值之上。

这 4 条属于「剩余未能判断的案例」，只能靠模型自审 `grounded` 与用户核对两道关。
**本轮没有调整阈值**：把这 15 条分开的阈值大约在 0.79–0.80，但那是 15 条合成样本
上的过拟合，全局上调会在真实长回答上造成大规模误伤（比漏放更糟）。
已固化为边界测试 `test_gate_catches_unsupported_numbers_but_not_vague_action_claims`。

4. 人工维度仍为 `UNRATED`；没有人工金标准，不计算「事实错误率」这个指标。
