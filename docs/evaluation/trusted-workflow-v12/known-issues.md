## P1 · 已确认档案改共享事实的入口很窄，字段级同步在产品里够不到

**现象**
确认简历来源（岗位流程必经的一步）会把档案从 `DRAFT` 升位到 `CONFIRMED`。之后：

- `PUT /api/v1/profiles/{id}` → 409；
- `POST /profiles/{id}/resumes`（换文件）与 `/resumes/text`（重新解析）→ 409；
- 唯一能改共享事实的入口是 `POST /profiles/{id}/facts/attest` 且 `apply_to_source=true`（「核对 + 写回」同一次动作，前端在简历页的事实核对面板里）。

而 `apply_to_source` 只写回**描述类文本**。事实同步（`sync`）真正能更新的字段是 `title / organization / dates`，这些字段在已确认档案上**没有可达的改法**。

**影响**
- 能改：技能名、经历描述（→ 影响面提示、占位提示都能正常出来）；
- 改不动：经历时间、职位名、组织名（→ 这些字段的 `sync` 只能被 DRAFT 档案走到，即「还没确认过简历来源」的早期阶段）。
- 经历描述属于 AI 改写要点，按设计**不会**被 `sync` 自动改写（只提示「需要你确认或重新生成」）。所以「改了共享事实 → 自动同步进三份岗位简历」这条链路，在产品里只有技能类事实能真正跑通。

**为什么没直接改**
`tests/test_profiles.py::test_confirmed_profile_cannot_be_edited` 明确锁死了这条规则。它是既有产品决策，本轮的约束是「不新增大功能开发」，我不想单方面推翻一条被测试固化的语义。

**建议（需要你拍板，任选一）**
1. 把 `CONFIRMED` 的语义收窄为「档案已就绪」，放开逐字段修正（保留「用新文件整体覆盖」的 409）；配套改 `test_confirmed_profile_cannot_be_edited`；
2. 给「改经历时间 / 职位名」开一个显式的单字段接口，并让它同样走「核对 + 写回」；
3. 维持现状，但在 UI 上对改不动的字段明说原因。

**当前缓解**：`invalidate_changed_attestations` 已保证任何一次事实变更都会撤销旧签名，不会出现「改了还挂着已确认」。

## P1 · 事实签名的比对文本不含时间

`fact_trust_service._iter_facts` 拼的是「标题 / 组织 / 描述」，**时间不在里面**。所以改经历的 `dates` 不会触发签名失效。

影响面：只在 DRAFT 档案上可达（见上一条），实际风险被上一条覆盖住了。但要修，正确做法是把 `dates` 一并纳入比对文本——这会改变事实核对面板显示的 `original_text`，属于可见改动，本轮没做。

## P2 · 事实闸门是保守的，不是完备的

- 高风险词表与覆盖率阈值（`COVERAGE_THRESHOLD=0.45`）是经验值，存在漏网与误伤；
- 闸门查不出「有依据但被错误拼接」的表述（数字来自 A 经历、动作来自 B 经历，各自都能在语料里找到）；
- 对抗样本是人工构造的，没覆盖真实 JD / 真实简历分布。

**不做「未检出编造 ⇒ 系统不会编造」的推断。** 闸门的方向是「不确定一律降级」，这能显著降低风险，但不能证明为零。

## P2 · 离线基准里 interview 套件仍有 5 次参考答案事实错误

RUN_ID `offline-all-20261018T165202Z`：`reference_answer_fact_error_count = 5`，`jd_grounded=0.733`、`resume_grounded=0.667`。

这些是在**没有开事实闸门**的对照路径上统计出来的——正是 Sprint A 要拦的那类输出；开了闸门后对应的对抗用例全部被拦。**但基准脚本本身没有把闸门接进去跑**，所以这个数字目前只说明「模型确实会编造」，不能说明「产品放行了编造」。要把它变成有意义的指标，需要加一组「开闸门后」的对照。

另外：`human_dimensions = UNRATED`、`adoption_rate = null` —— 人工维度没评，不能拿自动指标冒充人工结论。

## P2 · 浏览器 E2E 的模型是桩

6 条主流程 35/35 通过，但模型侧是本地桩：改写只照抄源事实、参考回答故意编造。验证的是**产品流程与前端行为**，不是模型输出质量。真实模型下的表现 `NOT_RUN`（本轮未授权付费调用）。

桩本身也踩过坑：提示词路由靠关键词匹配，一度把「岗位简历生成」误判成「面试提问」导致 502。已修，但这说明桩的可信度依赖路由正确性。
