# AI Career OS — PRODUCT GLOSSARY

**用途：** 项目过程中第一次遇到专业词时，用自己的项目场景解释。不要死背定义。

| Term | 中文 | 在本项目里是什么意思 |
|---|---|---|
| PRD | 产品需求文档 | 说明给谁用、解决什么问题、MVP 做什么、不做什么、做到什么算完成 |
| MVP | 最小可行产品 | 最小但完整地证明核心价值的版本 |
| P0 | 必须有 | 没有它 Critical Path 就走不通 |
| P1 | 重要但可延后 | MVP 不做也能证明核心价值 |
| P2 | 后续增强 | 价值存在，但当前不投入 |
| Critical Path | 关键路径 | 用户从进入产品到获得核心价值的最短必经路径 |
| Happy Path | 主成功路径 | 先按正常输入、正常运行设计的主流程 |
| Scope | 范围 | 当前版本明确做什么 |
| Scope Freeze | 范围冻结 | PRD 批准后不随意加需求 |
| Out of Scope | 非范围 | 当前版本明确不做什么 |
| Backlog | 需求池 | 有价值但当前不做的需求集合 |
| Acceptance Criteria | 验收标准 | 功能满足哪些可测试条件才算完成 |
| User Outcome | 用户结果 | 用户最终获得什么，而不是产品“做了什么” |
| Feature | 功能 | 产品提供的能力，例如上传简历 |
| Value Proposition | 价值主张 | 为什么用户要用 Career OS，而不是直接用 ChatGPT |
| Onboarding | 首次使用流程 | 第一次建立用户画像的过程 |
| Friction | 使用摩擦 | 用户完成操作需要付出的麻烦 |
| Draft Profile | 草稿画像 | AI 提取但用户尚未确认的画像 |
| Confirmed Profile | 已确认画像 | 用户检查后可作为后续事实的数据 |
| Evidence | 证据 | 支撑推荐和 Gap 判断的真实来源 |
| Source of Truth | 事实主来源 | 冲突时某类问题优先依据哪个数据源 |
| Grounding | 依据约束 | 先检索真实资料，再让模型基于资料回答 |
| Gap | 差距 | 用户当前状态与目标岗位要求之间的差异 |
| Actionable Gap | 可行动差距 | 能通过学习/项目等短期行动改善 |
| Structural Constraint | 结构性约束 | 学历、工作年限等短期难直接改变的条件 |
| Prioritization | 优先级排序 | 从很多 Gap 中确定现在最值得解决的几个 |
| User Override | 用户覆盖 | 用户可以覆盖 AI 默认推荐 |
| Soft Guardrail | 软护栏 | AI 提醒风险，但不阻止用户选择 |
| Roadmap | 路线图 | 从当前状态到目标的阶段规划 |
| Milestone | 里程碑 | 可验证的阶段成果 |
| Daily Task | 每日任务 | 当天具体可执行动作 |
| State | 状态 | 系统当前记录的用户目标、能力、进度等事实 |
| Replanning | 重规划 | 根据新状态调整后续计划 |
| Manual Trigger | 手动触发 | 用户主动点击或表达需求后才执行 |
| Dashboard | 仪表盘 | 结构化展示目标、Gap、任务和进度的主页 |
| Evidence Trace | 证据追踪 | 可以看到一个判断具体依据了哪些 JD / 用户信息 |
| JD Aggregation | JD 聚合 | 对多个同类 JD 做共性和差异分析 |
| Skill Normalization | 技能标准化 | 将 LLM/大语言模型等同义写法统一 |
| Capability | 核心能力 | 一个用户可感知、工程上可交付的完整能力 |
| Vertical Slice | 垂直切片 | 尽早跑通一条从前端到后端、AI、数据库的完整小闭环 |
| Trade-off | 权衡 | 没有绝对最好，需要在速度、准确性、复杂度等之间取舍 |
| Change Request | 变更请求 | Scope Freeze 后希望修改 MVP 的正式申请 |
| ADR / Decision Record | 决策记录 | 记录为什么选 A 而没选 B |
