## 浏览器验收

API 和页面连接到系统临时目录中的独立 SQLite 文件；仅使用合成岗位和合成简历。测试库通过 SQLAlchemy `Base.metadata.create_all` 建表，未使用指向其他环境的默认 `DATABASE_URL`。
五轮面试测试结束后，已停止本地测试 provider，并以普通 API 启动方式连接同一隔离库；`/health` 返回 `ok`，Web `/missions` 返回 HTTP 200。此预览仍是本机隔离数据，不是部署环境。

## 已知限制与后续项

1. 合成岗位的模型生成内容发生跨岗位素材混入：Baidu 问题预览出现“商汤科技 curated AI_PRODUCT interview signals”，小红书岗位的建议项目出现不相关的智能硬件内容。这是生成结果/情报来源的相关性问题；本轮没有修改生成 provider。实际使用时应人工审阅并排除不相关建议。
2. 简历解析对结构松散的合成文本只提取出技能；重试规范化格式后提取完整。界面已将“粘贴文本失败”提示与 PDF 失败提示区分。
3. 当前导出调用浏览器打印预览，由用户选择“另存为 PDF”。浏览器自动化未观察到本地最终 PDF 文件，因此仅验证预览入口和导出检查。
4. 长任务超时目前使 UI 可重试，但 `Promise.race` 不会取消已经发送到服务器的请求。极慢请求与立即重试可能并行；后续可为相关请求加入取消信号或幂等键。

## QA 判断

漏项：真实 provider 的答案质量和来源相关性、打印对话框外的最终 PDF 文件尚未验证；手机端已覆盖岗位、来源、改写、最终预览、评分和复盘。

高价值改进：在问题预览与简历建议入库前增加“岗位公司与能力主题一致性”校验，并展示被过滤原因，避免跨岗位内容进入用户决策。
