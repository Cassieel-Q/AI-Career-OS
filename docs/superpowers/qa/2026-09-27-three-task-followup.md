# 2026-09-27 三任务跟进：简历改写与模拟面试

## 用户路径审计

1. 从岗位的「简历优化」进入目标简历：同一原经历有多条 AI 改写时，原 UI 只展示操作按钮，接受/拒绝状态不明显，且 API 允许同时接受多个版本。
2. 从已确认简历进入「模拟面试」：旧入口使用 proof 链路；首次 mission snapshot 可能只有岗位、没有 claim，路由守卫会把用户送回旧的「简历建议」步骤。问题生成请求没有超时提示，用户只能看到长时间等待。
3. 面试回答后，按钮原文是「继续：复盘」，但实际流程会提交答案、评分并停留在 interview 生成下一题，文案与实际行为不一致。

## 本轮修复

- 以 `target_resume_id + source_experience_id` 为互斥组；接受或编辑一个版本时，其余版本原子标记为 `REJECTED`。确认旧草稿时也会清理历史上重复的 `ACCEPTED/EDITED`。
- 优化页显示「已接受 / 已拒绝 / 已编辑」状态徽标及卡片边框，并明确「同一经历的下一条改写（只能选择一条）」。
- mission 面试深链在缺少 claim 时自动尝试生成 claim-analysis；生成失败或超过 45 秒时留在面试页并显示中文重试提示，不再跳回旧 P2。
- 面试开始和提交回答的请求增加 45 秒超时；题目生成期间禁用回答框，失败后显示可重试错误。
- 面试底部按钮按真实状态显示「提交回答并生成下一题」或「查看面试复盘」。

## 追加修复与验收（2026-09-27）

- 同一经历的改写从生成时就按第一条有真实来源的版本 `ACCEPTED`、其余版本 `REJECTED` 写入；接受或编辑其他版本时后端自动拒绝同组兄弟版本。`AI 建议：暂不放入` 的经历不会进入目标简历确认门槛，也不会要求用户逐条确认事实。
- 已将当前百度 AI 产品经理任务中的校园经历旧判断修正为：教学运行保障中心助理 `DEEMPHASIZE`，心理委员与纪律委员 `OMIT`，体育部副部长 `DEEMPHASIZE`；科研、竞赛和模拟研究保持重点展示。浏览器刷新后可见心理委员/纪律委员显示「暂不放入」。
- 面试后端增加重复题替换；轮次上限为 5。模型在第 5 轮漏返回 `gap_type` 时，服务端自动归类为 `EVIDENCE_GAP`，保留回答并完成复盘，不再返回 422 卡死。
- 前端完成态不再执行残留的提交闭包，直接进入复盘；完成态题号显示最后一轮。复盘页面现在展示总体表现、逐题问题/回答/评分/待加强点和项目补齐建议。
- 证明行动收敛为两项：`回答 3–5 个事实追问`、`补全项目背景 / 个人动作 / 结果`；旧的上传材料、无经历、不可主张卡片会被清理。
- 浏览器实测完成 5 轮：第 1–5 题均连续保存，未回跳第 1 题；复盘页面显示 5 道题的完整问答，补强页显示两项动作。模型请求优先调用 DeepSeek；本次第 5 轮出现 provider 缓慢/缺 gap，使用了服务端中文兜底并完成闭环。
