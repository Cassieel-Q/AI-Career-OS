# AI Career OS Resume Studio 设计规格

**日期：** 2026-10-08  
**状态：** 用户确认方案 A，并要求直接完成成品  
**基线：** `9f71c7a`；与 `aioscaree-UI` 独立工作树集成

## 目标与边界

在现有岗位定向改写之后提供完整简历工作台：18 套真实 Typst 模板（中文 9、英文 9）、完整画廊预览、点击预览编辑、经历和要点增删及同板块排序、事实追溯、真实页数和 PDF 下载。内容先完成，模板后精修；换模板不修改内容、不调用模型。

现有 `TargetResume` 是 AI 改写和人工取舍的输入账本。第一次进入工作台时，以已确认的最新 `TargetResume`、本岗位绑定的 Profile 和经历筛选生成工作台文档。此后工作台文档是该岗位最终简历的唯一可编辑版本；`TargetResume` 保留原改写、来源和状态用于追溯，不能在后台静默覆盖工作台。工作台最终确认后，面试优先读取其已确认修订版；没有工作台文档的历史任务继续读取 `TargetResume`。

内置 AI 对话界面不属于本轮。Agent 通过同一组文档读取与变更 API 协作，可先提出内容修改，再使用 `If-Match` 修订号提交；网页编辑使用相同契约。现有 AI 改写入口保持可用。

## 用户流程与页面

全局阶段仍为 `岗位 → 简历 → 模拟面试 → 面试记录`。简历阶段内部为 `确认改写 → 选择模板 → 可视化精修 → 事实核对 → 导出 PDF`。工作台是独立路由，避免继续扩张 `mission-page.tsx`；提供返回岗位页入口，遵循已批准的米白蓝色像素 UI 规格。桌面版为左侧板块与来源、中央实际页面、右侧字段编辑；窄屏改为预览和编辑切换，排序还提供键盘“上移/下移”。

画廊按中文/英文分组，每张卡片展示该模板用固定虚构样本实际渲染的完整页面，并可放大查看所有页。切换分组不改正文；选择与当前文档语言不一致的模板时只显示“需要先完成译文”，不会机械翻译或偷偷改变数据。文档语言由明确的内容编辑操作改变。画廊记忆各语言上次选择，只有用户选择动作改变当前模板。

编辑目标包括姓名、联系信息、板块标题、经历标题/副标题/日期/地点、要点。点击预览中的文字热区选择对应稳定 `node_id`，右侧显示编辑框、事实来源和状态；点击保存后服务端写入一个修订版，重新排版。允许新增、删除（软省略）、恢复和同一板块内拖拽排序；每次保存返回修订号。浏览器会话提供撤销/重做，刷新后恢复最近一次已保存版本。排序同时提供键盘按钮。所有未保存文本在渲染错误、409 冲突和网络错误时保留。

## 数据契约与迁移

只新增一个 `resume_studio_documents` 表：`id`、`mission_id`（唯一）、`source_target_resume_id`、`schema_version`、`revision`、`language`、`template_id`、`document_json`、`confirmed_revision`、`created_at`、`updated_at`。渲染产物不是事实源，缓存可删除、重建，不新增 artifact 表。迁移只建新表与索引，不重写历史 `TargetResume`。

`document_json` 为有序的 `basics / sections / entries / bullets` 树。每个可编辑文本节点都有稳定 UUID 形式的 `node_id`、`text`、`evidence_refs`、`source_kind`、`source_id`、`claim_status` 和服务端判定的 `risk_level`。从 `TargetResumeBullet` 转入的节点保留原 bullet UUID 为 `node_id`；新增节点用新 UUID，删除后不复用。`source_kind` 可为 profile、experience、target_bullet 或 user_entered；来源引用必须属于当前绑定 Profile 或原目标简历。数据不支持任意 Typst 代码；受限强调与 HTTPS 链接先解析再转义。

事实状态为 `CONFIRMED`、`NEEDS_CONFIRMATION`、`BLOCKED_MISSING`、`OMITTED`。内容接受与事实确认是两个独立维度。新写入且无来源的字段默认待确认；改动已有已确认字段的实质信息会回到待确认。高风险包括身份、联系方式、学校/学位、雇主、任职时间、论文/专利、量化指标与个人贡献升级；后端根据字段和文本计算风险，客户端不能降级。已省略内容保留追溯记录，但不排版、不阻止导出。仅被纳入 PDF 的高风险待确认或缺失阻塞节点阻止确认/导出；其余待确认显示提醒。人工确认操作记录当前修订、节点和时间，不能由换模板触发。

每个 PATCH 请求携带文档 `revision`，服务端以数据库条件更新实现乐观并发。修订不匹配返回 409 和服务端最新版；网页保留本地未保存稿并显示重载/复制草稿，Agent 调用端必须重新读取后合并，绝不以后保存覆盖先保存。恢复/撤销也是新的修订，不回退序列号。

## 模板、排版与许可

提供 9 个 AI Career OS 原创版式家族，各有中文和英文适配，合计 18 个独立 manifest 条目与真实 Typst 编译预览。九种版式在标题区、栏位、节标题、密度和分隔方式上有可见区别，保持正文可选中、黑白打印可读。所有模板只读取结构化文档，模板目录静态注册，不在数据库存模板源码。每条 manifest 记录 ID、语言、名称、版式、作者、`SPDX=LicenseRef-AICareerOS-Original`、固定源版本、字体名与字体许可/系统依赖。模板源与虚构样本均为本项目原创；第三方项目只提供产品机制参考，不复制模板或代码。尤其不引入 StoneLL1 注册表内三个 `NOASSERTION` 中文模板，也不复制 AGPL-3.0 或许可不明项目源码。

FastAPI 服务使用固定版本 Typst CLI 在隔离临时目录编译。用户文本严格转义，进程设置超时、输入长度限制和受控根目录。预览返回逐页 SVG、实际 PDF 页数和由 Typst 节点锚点生成的 `layout_map`；导出针对同一文档修订生成真实 PDF 字节。前端保存后以 300ms debounce 请求预览，丢弃旧修订响应；服务端按 `document hash + template version + Typst version + font profile` 缓存，并对相同 hash 的并发编译合并。渲染失败保留上次成功预览、显示错误与重试。缓存目录可清理，不存个人简历进 Git。

PDF 文件名使用清洗后的 `姓名-公司-岗位-简历语言.pdf`，缺失字段省略，不含手机号。导出前服务端复查当前 revision、事实阻塞、至少一条有效经历/要点、页数和生成 PDF 的有效性；PDF 文本抽取不能为空，姓名、关键标题/要点可抽取，提示 ATS/文本可选性风险但不宣称 ATS 通过率。默认目标 1–2 页，超出时明确提示并阻止标为“投递版”的确认；用户可编辑内容或切换模板再检查。PDF 包含 Unicode 文本和基本文档元数据。

字体优先使用可审计的开放字体；开发机系统字体仅作为本地回退，不随产品分发。CI 与发布验收记录 `typst fonts` 输出和实际字体配置；缺字时显示具体错误。第三方通知记录 Typst、所用依赖和字体的版本、来源、许可，任何新模板或字体均须先通过许可审计。

## API 与既有流程衔接

- `GET /job-missions/{id}/resume-studio`：懒初始化并返回文档、revision、阻塞摘要。
- `PATCH /job-missions/{id}/resume-studio`：`If-Match` 修订号，提交单个编辑/增删/移动/事实操作，返回新文档。
- `GET /resume-studio/templates`：静态 manifest、完整样本预览 URL。
- `GET /job-missions/{id}/resume-studio/source-diff`：只读比较新版已确认改写稿与当前工作台。
- `POST /job-missions/{id}/resume-studio/reimport`：携带 `If-Match`，用户明确选择后重新导入新版并生成新修订号。
- `POST /job-missions/{id}/resume-studio/preview`：按当前已保存 revision 渲染页面、页数、热区。
- `POST /job-missions/{id}/resume-studio/confirm`：通过事实与排版门槛后标记 `confirmed_revision`。
- `GET /job-missions/{id}/resume-studio/pdf`：只下载已确认且仍为当前 revision 的 PDF；内容改变后须重新确认。

现有 `confirm-target-resume` 继续负责改写取舍，不再暗示 Studio 终稿已确认。面试上下文优先读取 `confirmed_revision == revision` 的 Studio 文档，并在面试开始时保存修订标识；历史任务退回现有逻辑。更换简历来源或重新生成目标简历时，现有 Studio 文档标记需重新导入，不能静默替换用户精修内容；导入前展示差异并由用户主动选择。

## 验收

1. 18 个 manifest 各自用 Typst 实际编译完整样本；中文 9、英文 9 均可全页预览。
2. 两份不同简历与两种语言完成生成、保存、刷新恢复、增删、排序、撤销/重做、换模板内容不变、点击预览编辑。
3. 四态事实筛选与高风险门槛正确；已省略不阻塞；并发冲突不丢草稿。
4. 真实 PDF 可下载、页数与预览一致、文件名安全、文字可抽取，编译失败可重试。
5. 原岗位改写与历史面试流程保持可用，新的面试上下文读取 Studio 确认修订。
6. 桌面和窄屏浏览器 E2E、18 模板截图、许可/字体/第三方通知审计通过。

## 主要风险与决策

最大实施风险是预览热区与不同模板的真实排版位置一致性；统一原创模板生成器和 Typst 锚点契约降低适配成本。第二个风险是最终简历真相源分叉；明确一次性从 TargetResume 导入、Studio 为最终修订、面试优先已确认 Studio，且来源改变不自动覆盖。性能目标为已缓存预览 300ms 内返回，暖机后的 1–2 页编译 2s 内返回；测试记录实际分布，超出则优化缓存和字体配置。
