# AI Career OS 文案与克制像素 UI 设计规格

**日期：** 2026-10-07  
**状态：** 用户已确认设计方向  
**适用项目：** `G:\myself\ai-career`  
**视觉参考：** [Todari/react-pixel-ui](https://github.com/Todari/react-pixel-ui)

## 1. 目标

将当前 AI Career OS 的用户界面统一为成熟、直接的求职工作台，并以克制的现代像素语言重做视觉与交互。

本轮需要同时完成：

1. 清理所有用户可见文案，去除说明书语气、幼态问句、后台实现解释和重复的“下一步”。
2. 建立米色、暖白色和稳重蓝色组成的视觉系统。
3. 使用像素边框、阶梯角、硬阴影、像素状态符号和短促按压反馈形成风格。
4. 增加清晰的全局流程进度条，让用户始终知道当前位于哪个阶段、已经完成什么、接下来是什么。
5. 为 JD 识别、简历解析、简历优化、问题生成和评分等长任务显示真实阶段状态，不使用虚假百分比。
6. 保持现有业务链路、数据库和 API 契约，不增加新的产品概念。

## 2. 非目标

- 不把产品改成 RPG、关卡或游戏任务。
- 不使用游戏化台词、角色属性、经验值、音效或粒子。
- 不对简历正文、JD、面试问题和长回答使用像素字体。
- 不重新设计数据库。
- 不修改已确认的核心用户链路。
- 不用大规模动画掩盖 API 延迟。

## 3. 文案原则

### 3.1 产品身份

产品以“专业工作台”的身份说话。界面负责说明当前对象、可执行动作和结果，不向用户解释后台 AI 实现。

### 3.2 规则

- 标题使用明确名词或动作。
- 描述最多两句，每句只表达一件事。
- 按钮使用动词加对象或动词加结果。
- 除真实面试问题外，页面标题不使用问号。
- 避免“你想……”“只需要……”“AI 会……”“让 AI……”“带着你……”等措辞。
- 避免在用户界面出现 workflow、claim、evidence、P1/P2/P3、proof action 等内部术语。
- 不把算法约束写成营销承诺，例如“AI 只修改最相关的 3～4 条”。
- 加载文案说明当前工作，不使用空泛的“处理中”。

### 3.3 统一术语

使用：

- 岗位档案
- 简历来源
- 原始简历
- 岗位定向版本
- 确认版本
- 问题预览
- 模拟面试
- 本题反馈
- 面试复盘
- 补强建议

避免：

- 准备链
- 面试拷问
- 主张核对
- 证明行动
- 可提交证明
- AI 告诉你下一步怎么做

### 3.4 基准改写

| 现有文案 | 新文案 |
|---|---|
| 准备一个新岗位 | 新建岗位 |
| 你想准备哪个岗位？ | 添加目标岗位 |
| 只需要粘贴岗位描述。公司、岗位、级别和要求会自动识别，识别后你可以确认或修改。 | 粘贴完整 JD，并确认岗位信息。 |
| 分析这个岗位 | 识别岗位信息 |
| 选择简历 | 简历来源 |
| 选择一份真实简历，AI 只修改与目标岗位最相关的 3～4 条内容，并保留原有结构。 | 选择已有简历，或为当前岗位上传新版本。 |
| 原始简历 → 针对当前 JD 的 AI 优化版本 | 原始简历 / 岗位定向版本 |
| 让 AI 告诉你下一步怎么补强 | 补强建议 |
| 看看这次表现 | 面试复盘 |
| 基于最终简历开始模拟面试 | 开始模拟面试 |

## 4. 视觉系统

### 4.1 色彩令牌

```css
--canvas: #f3efe5;
--surface: #fffefa;
--surface-muted: #e9eef8;
--primary: #3159b8;
--primary-hover: #24489a;
--primary-soft: #dce6ff;
--ink: #172033;
--ink-muted: #5c6475;
--pixel-border: #23304a;
--disabled: #cbc7be;
--danger: #b84444;
--warning: #a66b18;
--success: #2f6f62;
```

红、琥珀和绿色仅用于错误、警告和成功语义，不参与主要品牌配色。

### 4.2 字体

- 中文正文使用系统无衬线字体或现有高可读中文字体。
- 像素字体只用于步骤编号、小标签、状态徽章和极短英文标记。
- 正文、简历、JD、问题、回答和说明保持普通字体。

### 4.3 形状与阴影

- 主卡片使用 2px 深蓝灰边框。
- 卡片使用小幅阶梯角，视觉半径等效不超过 6px。
- 阴影使用向右下偏移的硬阴影，不使用模糊。
- 输入框可保留最多 4px 的轻微圆角，保证长文本编辑舒适。
- 不对整个页面应用像素滤镜。

### 4.4 react-pixel-ui 使用边界

参考 `react-pixel-ui` 的真实 DOM、阶梯角和硬阴影方法。实现时优先建立本项目自己的 CSS token 和共享组件；只在按钮、状态徽章、进度节点和卡片外壳中使用像素化封装。长文本、表格、textarea 和简历正文保持普通 DOM/CSS。

如直接引入 `@react-pixel-ui/react`，必须先验证：

- Next.js App Router SSR 不产生 hydration mismatch。
- 页面加载前后无布局跳动。
- 键盘操作、焦点和屏幕阅读器语义保留。
- 未通过验证时使用相同视觉规范的 CSS 实现，不阻塞整体改造。

## 5. 全局流程进度条

### 5.1 阶段

所有岗位任务页面顶部显示同一个流程进度条：

```text
01 岗位 ── 02 简历 ── 03 模拟面试 ── 04 面试记录
```

### 5.2 状态

- 当前阶段：蓝色实心像素节点，文字使用主要文字色。
- 已完成：蓝色勾选节点，可点击返回。
- 可进入：白底深色边框节点，可点击。
- 尚未开放：暖灰节点，不可点击，提供可理解的原因。
- 连接线按完成范围填充蓝色。
- 移动端改为两行紧凑布局，不能横向溢出。

### 5.3 交互

- 点击已完成阶段可返回查看，不能清空现有结果。
- 点击当前阶段不重新请求 API。
- 未开放阶段不响应导航，并在邻近位置说明缺少的前置条件。
- 浏览器刷新后，进度必须由服务端已保存状态恢复。
- 不允许仅靠前端临时状态把步骤标成已完成。

## 6. 长任务内部进度

JD 识别、简历解析、岗位定向版本生成、面试问题生成和回答评分使用阶段式进度，不显示虚假百分比。

示例：

```text
✓ 读取岗位要求
■ 整理简历结构
□ 生成岗位版本
□ 检查事实边界
```

规则：

- 已完成阶段显示蓝色像素勾选。
- 当前阶段显示缓慢闪烁的蓝色方块。
- 待执行阶段使用空心方块。
- 原始输入和已经生成的内容保持可见。
- 超时或 API 错误后显示明确错误与“重新生成”。
- 重试不能清空用户输入和已确认状态。
- 不允许按钮无限停留在“正在生成”。

## 7. 组件交互

### 7.1 按钮

- 悬停：向左上移动 1px，硬阴影加深。
- 按下：向右下移动，阴影收回。
- 键盘焦点：显示 3px 蓝色像素焦点框。
- 加载：保持原宽度，文字切换为具体进行状态。
- 禁用：降低对比度，文字仍可读。
- 主按钮、次按钮、文字按钮和危险按钮有稳定层级。

### 7.2 可选卡片

- 整张卡片可点击。
- 悬停使用浅蓝背景。
- 选中使用蓝色边框、浅蓝背景和实心像素标记。
- 卡片内显示明确的“已选择”。
- 不仅依靠颜色区分状态。

### 7.3 输入与验证

- 使用固定标签，不使用浮动标签。
- 聚焦时使用蓝色边框和像素焦点框。
- 校验在失焦或提交后显示，不在每个字符输入时打断用户。
- 错误靠近对应输入框，保留用户输入。

### 7.4 动效

只保留按钮按压、卡片选中、状态切换和内容出现。单次动效 120–160ms。支持 `prefers-reduced-motion`，关闭位移与闪烁。

## 8. 页面设计

### 8.1 岗位列表

- 标题：`岗位档案`
- 主按钮：`新建岗位`
- 卡片显示公司、岗位、简历状态、面试状态和最近更新时间。
- 点击卡片主体进入岗位；删除使用独立危险操作。
- 空状态：`还没有岗位档案。添加 JD 后即可开始。`

### 8.2 新建岗位

- 小标签：`岗位档案`
- 标题：`添加目标岗位`
- 描述：`粘贴完整 JD，并确认岗位信息。`
- 主按钮：`识别岗位信息`
- 识别后原 JD 保持可见，下方逐项展示公司、岗位、级别和地点。
- 保存动作：`保存岗位`
- 错误后输入不丢失，按钮变为 `重新识别`。

### 8.3 简历来源

- 标题：`简历来源`
- 描述：`选择已有简历，或为当前岗位上传新版本。`
- 三种入口：已有简历、上传 PDF、粘贴文本。
- 切换入口不立即删除已有输入。
- PDF 显示文件名、解析状态和更换入口。

### 8.4 简历优化

- 桌面端左右双栏：`原始简历` / `岗位定向版本`。
- 右侧改写悬停时，左侧对应原文同步高亮。
- 点击左侧经历时，右侧滚动到对应改写。
- `接受 / 编辑 / 不采用` 为互斥状态。
- 接受同一经历的一条改写时，其余改写自动变为不采用。
- 状态文字固定显示 `已接受`、`已编辑` 或 `未采用`。
- 事实确认与内容接受保持独立。
- 建议补做项目标记为 `建议完成的作品集项目` 和 `尚未写入正式简历`。
- 底部显示真实确认进度，如 `已处理 8 / 10 项`。

### 8.5 最终简历

- 提供 `原始版本 / 岗位版本` 切换。
- 切换时保持当前阅读位置。
- 主要操作：`确认最终版本`、`导出 PDF`、`开始模拟面试`。
- 导出前集中显示检查结果。
- 建议项目未完成且未确认时不得进入 PDF。

### 8.6 问题预览

- 使用可展开的题目卡组。
- 卡片显示编号、能力主题、问题摘要和考察点。
- 当前卡片使用浅蓝选中态。
- 页面底部固定主操作 `开始模拟面试`。

### 8.7 模拟面试

- 问题卡片和回答框等宽。
- 回答框在问题生成前禁用，但页面显示具体进度。
- 提交后保留回答并显示 `正在评分…`。
- 评分完成后展示评分、做得好的地方、可以加强和参考回答。
- 下一题生成后显示 `进入下一题`，由用户主动切换。
- 不自动跳回第一题，不在评分出现后突然切换问题。

### 8.8 面试复盘与补强

- 顶部展示总体结论、做得好的地方和需要加强。
- 下方保留所有问题、回答和每题评分。
- 补强只保留：`继续追问`、`生成项目补强指南`。
- 继续追问生成 3–5 个事实问题。
- 项目补强指南包含背景、个人动作、决策、结果、应学知识和应形成材料。
- 不要求提交链接或证明材料。

## 9. 响应式

- 桌面端简历优化使用双栏。
- 小屏幕改为原文与改写成对排列，不使用横向滚动。
- 全局进度条在移动端分两行。
- 按钮在移动端保持至少 44px 点击高度。
- 面试回答框占可用宽度，不缩成窄列。

## 10. 无障碍

- 所有交互可通过键盘完成。
- 焦点可见，顺序与视觉顺序一致。
- 选中、完成、错误和禁用状态不能只靠颜色表达。
- 蓝色与米白背景上的文本达到 WCAG AA 对比度。
- 动效遵守 `prefers-reduced-motion`。
- 保持语义化 button、input、textarea、nav 和 heading。

## 11. 实现边界

- 建立统一设计 token 和共享 UI 原语，避免在页面文件重复硬编码样式。
- 文案集中维护可复用标签和状态映射。
- 不改变 API 路径、数据模型和数据库迁移。
- 不混入旧 P1/P2/P3 产品概念。
- 现有核心流程和测试继续有效。
- 当前浏览器扩展可能向 `<html>` 注入属性；根布局需容忍该类 hydration 噪声，同时不能掩盖应用自身的 hydration 问题。

## 12. 测试与验收

### 12.1 自动测试

- TypeScript 类型检查通过。
- 现有 Web 测试通过。
- 新增文案守卫，禁止用户界面重新出现已废弃术语。
- 新增流程进度条状态测试。
- 新增同一经历互斥选择和状态显示测试。
- 新增长任务失败、重试和保留输入测试。
- 对关键页面运行桌面与移动端截图检查。

### 12.2 E2E 验收

使用至少两个不同岗位和两份不同简历验证：

1. 新建岗位并确认识别结果。
2. 选择已有简历或上传新简历。
3. 生成岗位定向版本并逐条处理。
4. 确认最终版本并导出 PDF。
5. 生成问题预览。
6. 连续完成至少五道问题。
7. 查看完整面试复盘。
8. 生成继续追问和项目补强指南。
9. 刷新页面后全局进度正确恢复。
10. API 失败时输入和已完成结果不丢失。

### 12.3 视觉验收

- 主色只由米色、暖白和蓝色构成。
- 像素风清晰但不影响长文本阅读。
- 所有可点击区域都有悬停、按下、焦点和禁用状态。
- 页面不再出现说明书式文案和实现细节。
- 进度条在所有岗位任务页面一致。
- 加载状态不会无限停留。
