# Mission flow UX repair plan

## Goal

让岗位准备链路在“目标简历 → PDF 导出 → 压力测试 → 补强 → 单主张/完整面试”之间有明确、可回退且不死路的下一步。

## Scope

1. 统一面试页补强 CTA：首次进入使用“下一步：进入补强”，只有用户已经进入补强流程后才使用“返回补强”。
2. 将目标简历导出提升为确认后的正式阶段动作，明确“先导出投递版 PDF，再检查简历风险”。
3. 补强页根据主张和动作状态展示不同下一步：仍有未完成动作时继续补强；已有可追问主张时进入面试页并可单主张拷问；全岗达标时进入完整面试。
4. 先补状态层单元测试，再改 UI，最后用浏览器和 API 做端到端复测。

## Verification

- `npm run test -- --runInBand`（或项目等价测试命令）
- `npm run type-check`
- 强制刷新目标 mission 的简历、补强、面试三个 tab，验证 CTA、PDF 导出入口和单主张拷问入口。
